마킹에서 에이전트 수정 완료까지, 루프를 닫는 v3 제안

InstaFix의 존재 이유 — 내 웹앱의 UI/UX 문제를 화면에서 바로 마킹하고, 개발자가 스스로 기록하고, 그 기록을 LLM 에이전트에게 전달할 프롬프트로 만드는 도구 — 관점에서 현재 기능을 전수 점검한 결과와 업그레이드 제안.

01핵심 루프 진단

도구의 가치는 이 다섯 단계 루프가 얼마나 마찰 없이 도는가로 결정됩니다. 앞의 두 단계는 이번 시즌 작업으로 충분히 강해졌고, 병목은 뒤의 세 단계에 있습니다.

STEP 1
마킹
드래그 다중선택, 자동타겟, 키보드, 영역·텍스트, 단축키
탄탄함
STEP 2
기록
타입·음성·드래프트·스크린샷·진단 캡처
탄탄함
STEP 3
프롬프트
셀렉터·bounds 포함 마크다운. 그러나 소스 파일 힌트 없음
보강 필요
STEP 4
에이전트 전달
클립보드 복사가 유일한 통로. 파이프·MCP 없음
공백
STEP 5
완료 회수
에이전트가 상태를 닫을 방법이 프롬프트에 없음 → 수동 정리
공백

요약: 기록기로서는 완성 단계, 에이전트 도구로서는 절반. 프롬프트가 클립보드에서 끝나고, 수정이 끝나도 피드백은 열려 있는 채로 남습니다.

왜 P0인가 — 에이전트 정확도를 좌우하는 단일 최대 변수. InstaFix의 주 사용처가 바로 dev 서버 위의 자기 앱 리뷰이므로 적중 환경이 곧 주력 환경입니다. 상용 빌드에서는 기존 fail-closed 규율대로 조용히 생략되고 셀렉터 체계가 그대로 안전망이 됩니다.
P0클립보드 탈피 — instafix prompt CLI · MCP 서버effort M→L

채택 범위는 개발자가 통제하고 눈으로 확인하는 두 모드로 확정합니다. (MCP 자동 처리는 검토 후 제외 — §05 참조)

모드 A · 발주(새 세션) — 쌓아둔 항목 전체 또는 선택한 항목만, 별도의 Claude 세션에 배치로 던지는 작업 지시서. 내 작업 흐름과는 의도적으로 분리됩니다(나는 하던 일 계속).

npx @instafix/cli prompt --status open | claude -p       # 전체 발주
npx @instafix/cli prompt --id fb_x7k2,fb_m3q9 | claude -p # 선택 건만 발주

모드 B · 합류(현재 세션) — 작업 중이던 세션에서 /instafix 슬래시 커맨드(instafix init이 설치)로 목록을 확인하거나 열린 항목을 현재 컨텍스트로 끌어와 이어서 개발. 무엇이 들어오는지 개발자가 그 자리에서 봅니다.

"Agent에게" 버튼 — 위젯에서 현재 세션으로 밀어넣기

03기능 제안 — P1 · 기록의 밀도

P1"에이전트에 전달됨" 추적effort S

프롬프트 복사/내보내기 시각을 기록해 카드에 배지로 표시하고, 옵션으로 복사와 동시에 in_progress로 전환. 같은 건을 두 번 에이전트에 보내는 사고와 "이거 보냈던가?" 하는 기억 의존을 없앱니다.

리스트 카드 목업
#4버그진행 중⇥ 전달됨 · 12분 전
Vertex SaaS 카드를 클릭해도 아무 일도 없음
P1선택 항목만 프롬프트 복사effort S

지금은 "보이는 목록 전체"가 복사 단위입니다. 체크박스 다중선택(bulk bar)에 선택 N건 프롬프트 복사를 추가해, 이번 에이전트 세션에 넘길 묶음을 손으로 고를 수 있게 합니다.

P1프로젝트 지침 주입 — agentInstructionseffort S

프롬프트 상단 지시문이 고정 3줄입니다. 위젯 config로 프로젝트별 규칙("스타일은 shadcn 토큰만", "수정마다 vitest 실행")을 주입할 수 있게 하면, 붙여넣은 프롬프트가 프로젝트 컨벤션을 이미 알고 시작합니다.

04기능 제안 — P2 · 마무리와 검증

P2수정 검증 뷰 — 그때 스크린샷 vs 지금 화면effort M

에이전트가 resolved로 닫은 항목에 "확인하기": 캡처 당시 스크린샷과 현재 화면(같은 앵커로 재스크롤)을 나란히 보여주고, 개발자가 한 번에 승인 또는 반려(reopen). 루프의 마지막 조각인 사람의 검수를 10초짜리로 만듭니다.

P2클립보드 이미지 첨부effort M

컴포저 텍스트영역에 이미지 붙여넣기(⌘V) 허용 — 디자인 시안·타 앱 레퍼런스를 "이렇게 바꿔줘"의 근거로 첨부. 멀티모달 에이전트에게 그대로 전달됩니다.

P2전역 단축키를 도움말 오버레이에 통합effort S

패널의 ? 도움말에는 패널 내부 키만 있습니다. Alt+Shift+A T S V 전역 키를 같은 오버레이에 표기해 발견 가능성을 높입니다.

05검토 후 제외한 것들

제안했다가 논의를 거쳐 의도적으로 빼기로 한 항목 — 이유를 기록으로 남깁니다.

  • 제외MCP 서버의 자동 처리 — 남은 항목을 에이전트가 알아서 소비하는 방식은 개발자 통제 밖에서 토큰을 쓰고, 무엇이 왜 바뀌었는지 추적이 흐려집니다. 모드 A(발주)·모드 B(합류)만으로 "눈으로 확인하며 처리"가 충족되므로 채택하지 않습니다. 필요해지면 후일 재검토.
  • 제외심각도 필드(P0/P1/P2) — 문제를 발견한 순간의 기록은 빠를수록 좋은데, 필수 입력이 하나 더 늘면 마찰이 커집니다. 급한 정도는 메시지 본문("긴급:")이나 처리 순서 선택(선택 발주)으로 충분히 표현됩니다.

06UX 손질 목록 — 지금 있는 것 다듬기

이번 시즌 라이브 테스트 중 실측으로 확인했거나 구조적으로 확실한 항목만 담았습니다.

  • 버그Escape가 열린 다중선택 팝업을 닫지 못함 — 오버레이만 내려가고 컴포저가 고아로 남는 기존 버그. 재현 확인됨, 우선 수정 대상.
  • 안전삭제 취소(undo) 없음 — 확인 다이얼로그는 있지만 실수 삭제는 복구 불가. 5초 undo 토스트가 다이얼로그보다 빠르고 안전합니다.
  • 명료"프롬프트 복사"의 범위가 암묵적 — 현재 필터·검색이 걸린 "보이는 목록"이 복사됨. 미리보기 모달 제목에 "열림 12건 · 이 페이지" 식으로 범위를 명시해야 합니다.
  • 밀집마커 클러스터 위 툴팁 겹침 — 마커가 뭉친 지점에서 툴팁이 이웃 마커를 가림. 클러스터 펼침 중에는 툴팁을 지연시키는 것으로 완화 가능.
  • 일관위젯의 상태 어휘가 이분법 — 대시보드는 4상태(open/in_progress/resolved/wont_fix)인데 위젯 카드는 해결/재열기만 노출. "전달됨 추적"(§03)과 함께 in_progress를 위젯에도 승격시키는 것이 자연스럽습니다.

한 줄 결론 — 마킹과 기록은 이미 이 도구의 강점입니다. v3의 투자는 전부 "프롬프트 이후"에 몰아야 합니다: 프롬프트가 자기 ID와 완료 방법을 알고, 소스 파일을 가리키고, 터미널로 직접 흘러가며, 수정되면 목록이 스스로 닫히는 것. 그 순간 InstaFix는 기록 도구가 아니라 에이전트 작업 지시 시스템이 됩니다.
