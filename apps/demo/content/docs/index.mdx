---
title: What is InstaFix?
description: Point at the UI while a coding agent builds it, get a ready-made prompt — a self-hosted browser widget for agentic development.
---

Debugging with a coding agent? InstaFix lets you mark UI problems **directly on the page while the agent builds it**. Draw a rectangle — or click the toolbar's target button and click an element — type a short note, and it's saved pinned to the exact element, with a stable selector, a screenshot, and (in dev) which component rendered it. No more describing "the button at the top… no, the other one" in the chat.

Then hand it straight to the agent: every note is agent-ready Markdown from the moment it's saved — copy it, pipe it, or pull it into a session that's already running — and the agent closes it back out by ID once it's fixed. That's the whole point: **fewer round-trips typing out what's wrong, more time spent actually fixing it.** See [Agent workflow](/docs/agent-workflow) for the loop end to end.

## How it works

1. **You add the widget** to the app you're building — one `npm install`, one `initInstaFix()` call. Dev-only by default; it never shows to real visitors unless you pass `forceShow: true`.
2. **You mark what's wrong** — draw a rectangle, or click the target button and click any element. Each note is anchored to the DOM element under it, so it survives the agent reshuffling the layout. Optional extras: a screenshot of the annotated area, console/network diagnostics.
3. **The agent closes the loop** — grab it as agent-ready Markdown ([three ways](/docs/agent-workflow)), the agent fixes and resolves it by ID, and the list empties itself. Working with more than one person on the same project? The drop-in dashboard (a Linear-style inbox, keyboard-first) triages what's still open through `open` → `in_progress` → `resolved` / `wont_fix`.

## The pieces

| Package | What it is |
|---|---|
| [`@instafix/widget`](/docs/widget) | The feedback widget (~30 KB gzip, framework-agnostic, React hook included) |
| [`@instafix/adapter-fs`](/docs/adapters/fs) | Local, file-based store behind the [agent workflow](/docs/agent-workflow) — no database, `.instafix/history.jsonl` |
| [`@instafix/cli`](/docs/cli) | `init`, plus the [agent-loop commands](/docs/cli#agent-loop) — `prompt`, `resolve`, `watch`, `agent-setup` |
| [`@instafix/dashboard`](/docs/dashboard) | A triage inbox for when more than one person is working the list — one React component, or a headless hook |
| [`@instafix/adapter-prisma`](/docs/adapters/prisma) / [`-sqlite`](/docs/adapters/sqlite) | A real server-backed store for that team dashboard: one endpoint, auth, CORS, webhooks |
| [`@instafix/adapter-memory`](/docs/adapters/memory) / [`-localstorage`](/docs/adapters/localstorage) | Stores for tests, demos, and server-less prototypes |
| [`@instafix/adapter-kit`](/docs/adapters/writing-an-adapter) | Build your own store adapter — the contract, the engine, the conformance suite |

Ready? The [quickstart](/docs/quickstart) takes about three minutes — or try everything live in the [demo](/demo), which runs this very widget.
