`enableRightClickComment: true`를 설정하면, 페이지 어디서든 우클릭 시 커서 위치에 댓글 작성창이 열립니다 — 가능한 가장 빠른 "바로 이거" 피드백 방식입니다.

```ts
initInstaFix({
  endpoint: "/api/instafix",
  projectName: "my-project",
  enableRightClickComment: true,
});
```

기본값은 꺼짐입니다: 호스트가 명시적으로 활성화하지 않는 한 브라우저의 컨텍스트 메뉴를 가로채는 일은 절대 없습니다.

## 네이티브 메뉴가 우선하는 경우

다음 모든 경우에는 위젯이 브라우저 자체의 컨텍스트 메뉴에 양보하며, 아래 순서대로 확인합니다:

1. **이미 앱에서 처리한 경우** — 요소 레벨 핸들러가 먼저 `preventDefault()`를 호출했다면(데이터 그리드, 코드 에디터 등), 위젯은 물러납니다. 이 방식으로 자체 컨텍스트 메뉴가 필요한 영역을 지정할 수도 있습니다.
2. **키보드로 트리거된 메뉴** — ≣ Menu 키와 Shift+F10은 항상 네이티브 메뉴를 띄웁니다. (Pointer Events 명세에 따르면 키보드로 발생한 이벤트는 `pointerType: ""`를 가지며, 위젯은 정확히 이 값을 확인합니다.)
3. **보조 키(모디파이어)** — Shift, Ctrl, Alt, Meta와 함께 우클릭하면 항상 네이티브 메뉴로 넘어갑니다. 사용자와 개발자 도구 모두를 위한 만능 탈출구입니다.
4. **InstaFix 자체 UI** — 버튼, 패널, 마커, 또는 `data-instafix-ignore`가 지정된 요소를 우클릭하는 것은 무시됩니다.
5. **주석 작성 중** — 이미 댓글 팝업이 열려 있는 동안에는 우클릭이 평소대로 동작합니다(텍스트 영역에 붙여넣기를 할 수 있도록).

마우스 우클릭, 터치 롱프레스, 펜 롱프레스 모두 작성창을 엽니다. 태블릿에서는 위젯의 768px 이상 뷰포트 규칙과 자연스럽게 맞물립니다.

## 열리는 내용

이 즉시 실행 흐름은 커서 위치에 작은 점 주석을 생성하고, 즉시 작성창을 열며, 댓글을 그 아래 있는 요소에 고정합니다. 스크린샷 기능이 켜져 있다면 20픽셀짜리 점이 아니라 해당 요소의 영역 전체가 캡처됩니다.
