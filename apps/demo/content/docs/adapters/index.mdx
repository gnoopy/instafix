title: Choosing an adapter
description: Where your feedback lives — .instafix/ for solo agentic work, Prisma or SQLite for a team, memory/localStorage for tests and demos.
---

An adapter is the storage layer behind InstaFix. All of them implement the same `InstaFixStore` contract (6 methods), so you can swap them without touching the widget.

| Adapter | Where data lives | Use it for |
|---|---|---|
| [`@instafix/adapter-fs`](/docs/adapters/fs) | Plain files under `.instafix/` at your project root | Solo, agent-driven work — no database, what the [agent workflow](/docs/agent-workflow) is built around |
| [`@instafix/adapter-sqlite`](/docs/adapters/sqlite) | A local `.db` file, via better-sqlite3 | A real, durable store — no ORM or database server needed |
| [`@instafix/adapter-prisma`](/docs/adapters/prisma) | Your database, via Prisma | A real store — already on Prisma |
| [`@instafix/adapter-memory`](/docs/adapters/memory) | An in-process array | Tests, previews, throwaway demos |
| [`@instafix/adapter-localstorage`](/docs/adapters/localstorage) | Your own browser | Demos and prototypes — no server at all |

Not sure which one? Working solo with a coding agent — the common case — use `adapter-fs`. Need more than one person looking at the same list (the [dashboard](/docs/dashboard)), or already have Prisma set up? SQLite or Prisma give you a real, shared store. `npx github:gnoopy/instafix#cli-dist init` asks and wires up whichever you pick.

Need a different backend entirely (Postgres without Prisma, MongoDB, DynamoDB, …)? [Write your own](/docs/adapters/writing-an-adapter) with `@instafix/adapter-kit`.

## Two ways to mount a store

**Server mode** — the widget talks to an HTTP endpoint, and the endpoint talks to the store. This is the production shape:

```ts
// app/api/instafix/route.ts
import { createInstaFixHandler } from "@instafix/adapter-prisma";
import { prisma } from "@/lib/prisma";

export const { GET, POST, PATCH, DELETE, OPTIONS } = createInstaFixHandler({ prisma });
```

**Client-side mode** — the widget writes to a store directly in the browser, no server needed:

```ts
import { initInstaFix } from "@instafix/widget";
import { LocalStorageStore } from "@instafix/adapter-localstorage";

initInstaFix({ store: new LocalStorageStore(), projectName: "my-demo" });
```

> Writing your own adapter? Install `@instafix/adapter-kit`: snapshot backends get a complete store from `createCollectionStore`, query backends implement the 6 methods, and both verify with the shared conformance suite (44 tests). See [Writing an adapter](/docs/adapters/writing-an-adapter).
