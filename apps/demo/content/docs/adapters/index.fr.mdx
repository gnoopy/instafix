Un adapter, c'est la couche de stockage derrière InstaFix. Les trois implémentent le même contrat `InstaFixStore` (6 méthodes), vous pouvez donc les échanger sans toucher au widget.

| Adapter | Où vivent les données | À utiliser pour |
|---|---|---|
| [`@instafix/adapter-prisma`](/fr/docs/adapters/prisma) | Votre base de données, via Prisma | La production — l'installation standard |
| [`@instafix/adapter-memory`](/fr/docs/adapters/memory) | Un tableau en mémoire du processus | Tests, previews, démos jetables |
| [`@instafix/adapter-localstorage`](/fr/docs/adapters/localstorage) | Le navigateur du visiteur | Démos et prototypes côté client — aucun serveur |

Besoin d'un autre backend ? [Écrivez le vôtre](/fr/docs/adapters/writing-an-adapter) avec `@instafix/adapter-kit`.

## Deux façons de monter un store

**Mode serveur** — le widget parle à un endpoint HTTP, et l'endpoint parle au store. C'est la forme de production :

```ts
// app/api/instafix/route.ts
import { createInstaFixHandler } from "@instafix/adapter-prisma";
import { prisma } from "@/lib/prisma";

export const { GET, POST, PATCH, DELETE, OPTIONS } = createInstaFixHandler({ prisma });
```

**Mode côté client** — le widget écrit directement dans un store du navigateur, aucun serveur nécessaire :

```ts
import { initInstaFix } from "@instafix/widget";
import { LocalStorageStore } from "@instafix/adapter-localstorage";

initInstaFix({ store: new LocalStorageStore(), projectName: "ma-demo" });
```

> Vous écrivez votre propre adapter ? Installez `@instafix/adapter-kit` : les backends snapshot obtiennent un store complet via `createCollectionStore`, les backends à requêtes implémentent les 6 méthodes, et les deux se vérifient avec la suite de conformité partagée (44 tests). Voir [Écrire un adapter](/fr/docs/adapters/writing-an-adapter).
