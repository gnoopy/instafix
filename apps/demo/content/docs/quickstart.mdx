InstaFix isn't published to the npm registry — that's a deliberate choice, not a "not yet." Every package installs straight from this repo's build output, via a disposable `<package>-dist` branch: same install experience, just a GitHub URL instead of a package name.

Three paths, pick one: **solo, no database** (the default — `init` suggests this first), **working with a team** (a real, shared store behind the dashboard), or **zero-server** (60 seconds, everything in the browser).

## Solo, no database

Feedback lives as plain files under `.instafix/` at your project root — nothing to run, nothing to configure, and it's what the [agent workflow](/docs/agent-workflow) (`instafix prompt`/`resolve`/`watch`) reads and writes directly.

### 1. Scaffold

```bash
npx github:gnoopy/instafix#cli-dist init
```

No Prisma schema in your project? `init` asks how to store feedback and lists **"Local history (`.instafix/` folder)"** — pick it. It also generates a ready-to-use `components/instafix-widget.tsx` and installs the `/instafix` slash command.

### 2. Install what `init` referenced

```bash
npm install github:gnoopy/instafix#widget-dist github:gnoopy/instafix#adapter-fs-dist
```

### 3. Mount the widget

`init` already generated the component — drop it into your root layout:

```tsx
// app/layout.tsx
import { InstaFixWidget } from "@/components/instafix-widget";

// ...inside <body>, alongside your other providers:
<InstaFixWidget />
```

(Not using the generated component? The same thing, by hand: `useInstaFix({ endpoint: "/api/instafix", projectName: "my-project" })` from `@instafix/widget/react` in any client component.)

Run your dev server and look bottom-right: the InstaFix button is there. Draw a rectangle on anything, type a note, hit Send — it lands in `.instafix/history.jsonl`.

By default the widget shows in development but **never in production builds** — it's a tool for the people actively building the app, not something a real visitor should ever see. For a staging environment that builds in production mode, pass `forceShow: true`.

### 4. Hand it to your agent

```bash
npx github:gnoopy/instafix#cli-dist prompt --status open | claude -p
```

Or copy a single note from the panel ("Copy Prompt"), or type `/instafix` in a Claude Code session already running here. Once fixed, the agent closes it itself — see [Agent workflow](/docs/agent-workflow) for all three handoff paths and how `resolve` closes the loop.

## Working with a team

More than one person needs to see the same list? Swap `adapter-fs` for a real server-backed store and add the dashboard:

### 1. Scaffold, install, push

```bash
npx github:gnoopy/instafix#cli-dist init
```

A Prisma schema in your project gets a Prisma-backed route automatically; no schema prompts you to pick **SQLite** (`better-sqlite3`, zero external services) instead.

```bash
# Prisma path
npm install github:gnoopy/instafix#widget-dist github:gnoopy/instafix#adapter-prisma-dist
npx prisma db push

# SQLite path
npm install github:gnoopy/instafix#widget-dist github:gnoopy/instafix#adapter-sqlite-dist
```

Prisma path only: you'll need a client singleton at `@/lib/prisma`. If you don't have one:

```ts
// src/lib/prisma.ts
import { PrismaClient } from "@prisma/client";

const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient };
export const prisma = globalForPrisma.prisma ?? new PrismaClient();
if (process.env.NODE_ENV !== "production") globalForPrisma.prisma = prisma;
```

### 2. Mount the widget

Same as the solo path above — `init` generated `components/instafix-widget.tsx`; drop `<InstaFixWidget />` into your root layout.

### 3. Add the dashboard

```tsx
import { InstaFixInbox } from "@instafix/dashboard";

<InstaFixInbox projects="my-project" endpoint="/api/instafix" theme="auto" />
```

From here: [widget options](/docs/widget/configuration) · [screenshots](/docs/widget/screenshots) · [auth & security](/docs/adapters/prisma#the-security-model-honestly).

## Reference: zero-server (local) mode

Everything above assumes a server-side store — that's what the agent loop runs on: `instafix prompt`, `/instafix`, and the "To agent" button all read fix notes from the server (e.g. [the `.instafix/` folder](/docs/adapters/fs)), so a store that lives only in the browser can't feed them.

Local mode exists for the case where there is no server at all: a static site, a design mockup, a throwaway prototype. Fix notes stay in the visitor's own browser (localStorage) and never leave it:

```bash
npm install github:gnoopy/instafix#widget-dist github:gnoopy/instafix#adapter-localstorage-dist
```

```ts
import { initInstaFix } from "@instafix/widget";
import { LocalStorageStore } from "@instafix/adapter-localstorage";

initInstaFix({
  store: new LocalStorageStore(),
  projectName: "my-demo",
  forceShow: true,
});
```

This documentation site runs exactly this setup — try the widget right here. Full options and limits: [localStorage adapter](/docs/adapters/localstorage).
