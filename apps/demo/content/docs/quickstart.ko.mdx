InstaFix는 npm 레지스트리에 배포하지 않습니다 — "아직 안 했다"가 아니라 의도된 결정입니다. 모든 패키지는 이 저장소의 빌드 결과물에서, 일회성 `<package>-dist` 브랜치를 통해 바로 설치됩니다 — 설치 경험은 동일하고, 패키지 이름 대신 GitHub URL을 쓸 뿐입니다.

두 가지 방법이 있습니다: **완전 설정**(Next.js + 실제 데이터베이스 — 프로덕션 형태)과 **서버 없는 설정**(60초, 모든 것이 브라우저 안에서 이루어짐)입니다.

## 완전 설정 — Next.js + Prisma 또는 SQLite

### 1. 스캐폴드 생성

```bash
npx github:gnoopy/instafix#cli-dist init
```

Prisma 스키마가 있으면 `init`이 InstaFix 모델 추가와 Prisma 기반 API 라우트 생성을 제안합니다. **Prisma 스키마가 없다면?** 대신 **SQLite**를 제안합니다(`better-sqlite3`, 외부 서비스 전혀 불필요 — 별도 DB 서버도, 마이그레이션 단계도 없음). 무조건 Prisma를 가정하지 않습니다. 어느 쪽이든 바로 쓸 수 있는 `components/instafix-widget.tsx`도 함께 생성합니다.

### 2. `init`이 안내한 패키지 설치

```bash
# Prisma 경로
npm install github:gnoopy/instafix#widget-dist github:gnoopy/instafix#adapter-prisma-dist
npx prisma db push

# SQLite 경로
npm install github:gnoopy/instafix#widget-dist github:gnoopy/instafix#adapter-sqlite-dist
```

Prisma 경로만 해당: `@/lib/prisma`에 클라이언트 싱글턴이 필요합니다. 아직 없다면 다음과 같이 만드세요:

```ts
// src/lib/prisma.ts
import { PrismaClient } from "@prisma/client";

const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient };
export const prisma = globalForPrisma.prisma ?? new PrismaClient();
if (process.env.NODE_ENV !== "production") globalForPrisma.prisma = prisma;
```

### 3. 위젯 마운트하기

`init`이 이미 컴포넌트를 만들어 뒀습니다 — 루트 레이아웃에 넣기만 하면 됩니다:

```tsx
// app/layout.tsx
import { InstaFixWidget } from "@/components/instafix-widget";

// ...<body> 안, 다른 provider들과 함께:
<InstaFixWidget />
```

(생성된 컴포넌트를 안 쓰신다고요? 직접 똑같이: 아무 클라이언트 컴포넌트에서 `@instafix/widget/react`의 `useInstaFix({ endpoint: "/api/instafix", projectName: "my-project" })`를 호출하면 됩니다.)

개발 서버를 실행하고 화면 오른쪽 아래를 보세요: InstaFix 버튼이 보일 것입니다. 아무 곳에나 사각형을 그리고, 댓글을 입력한 뒤 전송을 누르세요.

위젯은 기본적으로 개발 환경에서는 표시되지만 **프로덕션 빌드에서는 절대 표시되지 않습니다** — 이는 의도된 동작입니다: 클라이언트는 dev/staging URL에서 검토하기 때문입니다. 프로덕션 모드로 빌드되는 스테이징 환경이라면 `forceShow: true`를 전달하세요.

### 4. 들어온 피드백 트리아지하기

```tsx
import { InstaFixInbox } from "@instafix/dashboard";

<InstaFixInbox projects="my-project" endpoint="/api/instafix" theme="auto" />
```

전체 흐름은 이게 전부입니다. 여기서 더 살펴볼 것들: [위젯 옵션](/ko/docs/widget/configuration) · [스크린샷](/ko/docs/widget/screenshots) · [인증과 보안](/ko/docs/adapters/prisma#the-security-model-honestly).

## 참고: 서버 없는 (로컬) 모드

위 내용은 모두 서버 사이드 스토어를 전제로 합니다 — 에이전트 루프가 그 위에서 돕니다: `instafix prompt`, `/instafix`, "Agent에게" 버튼은 전부 서버(예: [`.instafix/` 폴더](/ko/docs/adapters/fs))에서 픽스노트를 읽으므로, 브라우저 안에만 있는 스토어로는 이 워크플로우를 쓸 수 없습니다.

로컬 모드는 서버가 아예 없는 경우를 위한 것입니다: 정적 사이트, 디자인 목업, 일회성 프로토타입. 픽스노트는 방문자 자신의 브라우저(localStorage)에만 저장되고 밖으로 나가지 않습니다:

```bash
npm install github:gnoopy/instafix#widget-dist github:gnoopy/instafix#adapter-localstorage-dist
```

```ts
import { initInstaFix } from "@instafix/widget";
import { LocalStorageStore } from "@instafix/adapter-localstorage";

initInstaFix({
  store: new LocalStorageStore(),
  projectName: "my-demo",
  forceShow: true,
});
```

이 문서 사이트도 정확히 이 설정으로 동작합니다 — 바로 여기서 위젯을 직접 사용해 보세요. 전체 옵션과 한계: [localStorage 어댑터](/ko/docs/adapters/localstorage).
